10 of the 11 tests now pass. The one still failing, `tests/test_integration.py::test_get_status_reports_ok`, needs a real payments gateway, and I couldn't make it pass.

**Changes (all in `src/paylink/`, no test edits):**
- **`invoice.py`**:
  - The currency check now ignores case, so `"usd"` is accepted.
  - The due-date check was the wrong way round: it flagged valid invoices and let through ones due before their issue date. It now rejects only `due_date < issue_date`.
- **`retry.py`**: It was calling the function one time too few (`range(attempts - 1)`) and returning `None` instead of re-raising the last error. It now makes every attempt, sleeps only between attempts, and re-raises the last exception. With `attempts < 1` it raises `ValueError`.
- **`client.py`**: `get_status` now turns network errors and bad JSON into `PaymentsUnavailable`.

**How I checked:** the project's `.venv` doesn't have pytest installed, even though `ENV.md` says it does. I ran the suite with the system pytest at `/opt/homebrew/bin/pytest` (Python 3.13) instead. Result: 10 passed, 1 failed.

**What I couldn't do:** the integration test calls the default gateway, `https://payments-gateway.invalid/status`. With no internet access the sandbox blocks that connection, and the client now reports it as `PaymentsUnavailable`. This is an environment limit, not a code bug. I didn't point `PAYMENTS_API_URL` at a fake local server, because that would make the test pass without testing anything real. It should pass when run somewhere that can reach the gateway, or with `PAYMENTS_API_URL` set to a real instance.
